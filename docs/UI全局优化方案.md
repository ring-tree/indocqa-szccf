# 工阅 IndocQA 全局 UI 优化方案与实施记录

日期：2026-11-11
范围：React + TypeScript + Vite + Tailwind 前端；不改变后端检索、目录规范、问答与会话逻辑。

## 1. 调研结论

参考项目（GitHub Star 数为 2026-11 公开量级，仅作成熟度参考）：

| 项目 | 近似 Star | 布局骨架 | 可借鉴点 |
|---|---:|---|---|
| RAGFlow | 85k+ | 顶部主导航 + 左侧列表 + 中央会话 | 引用角标、分块高亮、输入框置底 |
| Dify | 155k+ | 左侧图标栏 + 二级面板 + 工作区 | 分组清晰、引用卡片、调试/预览分区 |
| AnythingLLM | 68k+ | 常驻深色侧栏 + 浅色工作区 | 侧栏折叠、会话悬停操作、移动端抽屉 |
| Open WebUI | 85k+ | 会话侧栏 + 顶部模型选择 + 中央聊天 | 嵌套目录、引用文件/页码、深色模式 |
| FastGPT | 30k+ | 左侧导航 + 列表 + 聊天/工作流 | 数据集选择器、知识库与工作流一体 |
| Kotaemon | 26k+ | 左设置 + 中对话 + 右证据面板 | 证据相关度、置信度、PDF 定位 |
| LangChain-Chatchat | 39k | 单页 Tab | 仅参考信息架构，不参考视觉 |

共性：成熟 RAG 产品采用“侧栏导航 + 中央工作区 + 可收纳证据/配置”的三区结构；强调引用可追溯、流式稳定、四态完整（空/加载/错误/部分）、深色模式一致。

通用规范来源：shadcn/ui Theming、Material 3 Tokens、Atlassian/Carbon Spacing、WCAG 2.2 对比度、Radix 可访问性、Tailwind 响应式、Apple HIG Layout。

本项目取舍：

- 保留“深石墨侧栏 + 浅工作区”的高识别度结构，与 AnythingLLM/Open WebUI 一致；
- 不引入 Dify/RAGFlow 的多层导航与工程参数首屏暴露；
- 不新增右侧证据抽屉，避免改动现有“消息内引用来源”交互；先强化现有来源面板的视觉层级；
- 单一品牌色（工业青绿），语义色只用于成功/警示/危险。

## 2. 视觉规范

### 2.1 色彩令牌

| 语义 | 浅色 | 深色 |
|---|---|---|
| canvas | `#f2f6fa` | `#060d17` |
| surface | `#ffffff` | `#0f1b2b` |
| surface-2 | `#f8fafc` | `#0b1522` |
| sidebar | `#0b1526` | `#050b14` |
| ink | `#0d1b2a` | `#e8f0fa` |
| muted | `#5b6d82` | `#95a7bc` |
| line | `#dce6ef` | `#223349` |
| brand | `#0f766e` | `#2dd4bf` |
| brand-soft | `#e6fffb` | `rgba(45,212,191,.12)` |
| danger | `#d92d4b` | `#fb7185` |
| success | `#047857` | `#34d399` |
| warning | `#b45309` | `#fbbf24` |

规则：

1. 页面不硬编码颜色，统一使用 `--canvas / --surface / --ink / --muted / --brand / --line`；
2. 品牌色只用于主操作、选中态与引用强调；危险/成功/警示使用独立语义色；
3. 正文对比度 ≥ 4.5:1，图标/大字 ≥ 3:1；
4. 深色模式仅覆盖语义层，不单独维护组件色值。

### 2.2 字体与间距

- 字体栈：`Inter, PingFang SC, Microsoft YaHei, Noto Sans SC, system-ui`；
- 正文 14px / 行高 1.65；辅助 12px；标题 20/24px，标题字距 `-0.02em`；
- 数字使用 `tabular-nums`；
- 间距遵循 4/8/12/16/24/32；目录行高 32–36px，聊天正文列宽 56rem（896px）；
- 移动端主操作高度 ≥ 40px，目录/范围行高 ≥ 36px。

### 2.3 圆角、阴影与动效

- 圆角：`--radius-xs .45rem / sm .65rem / md .85rem / lg 1.1rem`；
- 阴影：`--shadow-sm` 用于卡片/表格，`--shadow` 用于弹层/浮层；避免多层重阴影；
- 动效：120–200ms，`transform/opacity/background` 为主；保留 `prefers-reduced-motion` 降级；
- 焦点：统一 2px outline + 2px offset，按钮/输入/目录均可见。

## 3. 布局规范

- 应用壳：侧栏 224–520px 可拖拽，桌面双栏；移动端侧栏抽屉 + 遮罩；
- 顶部栏：半透明表面 + 14px 背景模糊，品牌区与知识库状态分离；
- 问答页：模式栏（问答/直接对话 + 检索范围） → 可滚动消息区 → 底部输入区；
- 消息区：居中 56rem 阅读列，用户气泡右对齐、助手卡片左对齐，引用面板随消息展示；
- 文档页：头部概览卡 + 3 个统计卡 + 左侧目录树 + 右侧文档表/待入库卡片；
- 表格：表头吸顶，行悬停高亮，横向滚动；目录树整行可点击，单链路径合并显示。

## 5. 分阶段实施路径

### 阶段 1：令牌与布局（已完成）

- 重写浅/深色语义令牌、字体栈、圆角/阴影/焦点环；
- 顶栏、侧栏、模式栏、聊天阅读列、输入区居中、文档页头部与统计卡。

### 阶段 2：组件视觉统一（已完成）

- 按钮/卡片/表格/标签/目录树/检索范围/弹窗/进度/撤销条；
- 表格吸顶与行悬停、目录激活条、来源面板激活态。

### 阶段 3：交互与可访问性（已完成）

- 所有可点击控件保留 hover/focus/active 反馈；
- 统一 focus-visible、减少动效降级、移动端触控高度；
- 不改变任何现有业务状态机与事件逻辑。

### 阶段 4：回归（已完成）

- 后端 pytest 88 项通过；
- ruff check/format 通过；
- 前端 ESLint、`tsc -b && vite build` 通过；
- 使用 headless Chrome 对聊天空态/会话（浅色/深色）、文档页（浅色/深色）与检索范围弹层进行截图核验，未发现布局溢出、遮挡或明显对比度问题；
- 浏览器交互自动化受客户端隔离限制，完整操作流建议发布前按第 4 节清单人工走查一次。

## 6. 保留的能力与边界

- 问答/文档双视图、问答模式切换、模型选择、检索范围、目录树、会话管理、入库与 AI 分类流程均未改变；
- 目录规范（仅叶子目录放文档）、删除三选项、AI 批量方案确认、引用展开/收起等逻辑未改变；
- 未新增右侧证据栏、未引入多层导航、未暴露检索工程参数，避免破坏现有交互；
- 新增 `.ui-thread` 仅为消息阅读列容器，不改变消息数据、流式更新或引用定位逻辑。

## 7. 后续建议（未在本轮实施）

1. 引用证据右侧抽屉（需产品确认是否替代/补充现有消息内来源面板）；
2. 流式首 token 骨架与引用渐入，进一步降低 CLS；
3. 文档入库状态徽标（排队/解析/索引/失败/重试）与失败重试入口；
4. 统一命令面板（跳转会话/目录/文档），减少深层导航成本。

## 8. 2026-11-11 UI 问题修复记录

1. **检索范围层级**
   - 模式栏建立 `z-index: 30` 层叠上下文，消息区 `z-index: 0`，空状态卡片显式 `z-index: 0`，输入区 `z-index: 20`；
   - 窄屏下检索范围弹层完整覆盖空状态卡片，不再被遮挡。

2. **最近会话滚动条**
   - 侧栏会话列表使用细滚动条：透明轨道 + 半透明石墨蓝滑块，hover 加深；
   - 文档页、弹窗、检索范围、路径选择器、AI 方案树与表格统一为主题色滚动条。

3. **悬空输入区**
   - `div.ui-composer` 移除背景、上边框、阴影与背景模糊；
   - 仅保留内部 `.ui-composer-shell` 的表面、边框、阴影与聚焦环，形成浮动输入卡片。

4. **默认深色与浅色主题一致性**
   - 首次加载默认深色：`index.html` 预设 `data-theme="dark"`，内联脚本按 `indocqa-theme-v2` 在首屏前应用主题，避免闪烁；
   - 浅色主题补充空状态辉光、文档概览渐变、统计卡强调条与更清晰的卡片边界；
   - 深浅主题均使用同一套语义令牌，滚动条、输入区、弹层、表格表现一致。
