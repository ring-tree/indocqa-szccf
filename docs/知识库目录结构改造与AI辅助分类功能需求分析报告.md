## 1. 需求背景与目标

### 1.1 背景

知识库已完成"多级目录"第一阶段改造：文档具备 `folder` 元数据，后端支持目录 CRUD、文档移动与目录内检索；前端已有左侧目录树雏形与"行内下拉选择目录"的移动方式。

但当前交互仍以**列表为主、目录为辅**：移动文档依赖每行的下拉框，目录树只承担筛选职责。随着文档数量增长，管理员需要更符合直觉的"把文件拖进文件夹"的操作方式，以及更安全的误操作保护；同时，入库时的目录选择完全依赖人工判断，新用户面对空目录或陌生语料时决策成本高。

### 1.2 目标

1. 将目录树升级为知识库管理的**主交互入口**，支持拖拽移动、批量移动、二次确认与撤销；
2. 引入 **AI 辅助分类**，在入库和文档管理中给出可解释的目录建议，但不自动替用户做决定；
3. 保持现有检索、入库、目录范围过滤能力不变，改造可平滑上线、可回滚。

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 单篇文档移动操作步骤 | 从"找行→点下拉→选目录"3 步降为"拖拽→确认"2 步 |
| 移动误操作可恢复率 | 100%（8 秒内可撤销，或通过操作记录恢复） |
| 批量移动 20 篇文档耗时 | 一次操作完成，不需要逐行选择 |
| AI 推荐可用率 | 有明确候选（置信度≥60%）的文档占比 ≥80% |
| AI 推荐采纳率 | 内测期 ≥60% |
| AI 误分类导致的返工 | 0（AI 永不自动应用，必须人工确认） |

## 2. 现状分析与用户痛点

### 2.1 现状

| 能力 | 现状 |
|---|---|
| 目录展示 | 左侧目录树（全部/多级缩进/文档数），可筛选 |
| 文档移动 | 表格行内 `<select>` 选择目标目录，选中即移动 |
| 批量操作 | 无 |
| 移动确认 | 无 |
| 撤销 | 无 |
| 入库目录 | 使用当前选中目录，未选中则进入"未分类" |
| 目录检索 | 问答页"检索范围"下拉框 |

### 2.2 痛点（按影响排序）

| 编号 | 痛点 | 具体表现 | 影响用户 | 严重度 |
|---|---|---|---|---|
| PA-1 | 行内下拉没有空间感 | 目录以字符串形式出现在下拉框中，用户无法感知层级与相邻目录 | 管理员 | 高 |
| PA-2 | 单篇移动效率低 | 10 篇文档需要 10 次"找行→下拉→选择" | 管理员 | 高 |
| PA-3 | 无确认、无撤销 | 下拉选中即生效，误触后只能再选一次，且无法确认改到了哪里 | 管理员 | 高 |
| PA-4 | 目录树只读 | 树只能筛选，不能承接"移动"这一核心动作 | 管理员 | 高 |
| PA-5 | 入库目录决策成本高 | 新用户不知道应放哪个目录，容易全部堆到"未分类" | 录入人员 | 中 |
| PA-6 | 目录层级深时定位慢 | 下拉框不显示层级路径，同名末级目录无法区分 | 管理员 | 中 |
| PA-7 | 无批量选择 | 无法多选后统一移动/删除 | 管理员 | 中 |
| PA-8 | 移动结果反馈弱 | 移动后无提示，列表刷新后不确定是否成功 | 管理员 | 低 |

### 2.3 传统树形目录 vs 现有"列表+下拉"

| 维度 | 现有列表+下拉 | 传统树形目录（本次目标） | 结论 |
|---|---|---|---|
| 空间认知 | 弱，依赖文字 | 强，层级、兄弟目录可见 | 树形优 |
| 单篇移动 | 3 步 | 拖拽+确认 2 步 | 树形优 |
| 批量移动 | 不支持 | 多选后一次拖拽 | 树形优 |
| 小屏/无鼠标 | 可用 | 拖拽不可用，需键盘/菜单替代 | 需补降级方案 |
| 误操作风险 | 中（选中即生效） | 中（拖拽易误放），需确认+撤销 | 必须补安全机制 |
| 实现成本 | 已完成 | 中（前端交互为主，后端补批量/撤销） | 可接受 |
| 可发现性 | 高（下拉明显） | 中（需提示"可拖拽"） | 需空状态引导 |

## 3. 用户角色与核心场景

| 角色 | 目标 | 典型动作 |
|---|---|---|
| 知识库管理员 | 维护目录结构与文档归属 | 建目录、拖拽归档、批量整理、纠错 |
| 文档录入人员 | 快速入库且放对位置 | 上传、查看 AI 推荐、确认目录 |
| 现场工程师 | 快速找到资料 | 目录筛选、目录内问答（不参与管理） |
| 审计/评审人员 | 确认资料归档合规 | 查看目录结构、操作记录（P2） |

**核心场景**

1. 管理员把 15 份新手册从"未分类"批量拖到"设备手册/螺杆空压机"；
2. 录入人员上传一份 PDF，预检后看到"AI 推荐：行业标准/压缩空气系统 71%"，采纳或改选；
3. 管理员误把文档拖到错误目录，8 秒内点击"撤销"恢复；
4. 管理员把目录"设备手册"整体重命名，子树与文档归属同步更新；
5. 工程师在问答页选择"设备手册"范围提问，来源只出现该子树文档。

## 4. 需求范围与边界

### 4.1 范围内

- 目录树交互升级：展开/折叠、搜索、右键菜单、拖拽、批量移动；
- 移动安全机制：非法目标拦截、二次确认、8 秒撤销；
- AI 辅助分类：入口、计算状态、候选预览、采纳/调整/驳回；
- 入库路径选择：手动选择 + AI 推荐，单文件与批量；
- 后端支撑：批量移动、操作撤销、分类建议、反馈记录；
- 配套文档：需求分析报告、交互设计说明、任务跟踪清单。

### 4.2 范围外（本期不做）

- 目录级权限与多租户；
- 标签体系（一篇文档多标签）；
- AI 自动应用分类（无人工确认）；
- 目录拖拽排序（手动排序，当前按名称排序）；
- 跨知识库移动；
- 文档内容在线预览与 OCR。

### 4.3 关键假设

1. 一篇文档同一时间只属于一个目录（主目录），后续可用标签做交叉分类；
2. 目录最大 6 级、单级 ≤40 字、总长 ≤200 字（沿用现有约束）；
3. AI 推荐只作为建议，任何写操作必须人工确认；
4. 现有检索接口 `folder` 参数与目录子树过滤逻辑不变。

## 5. 可行性评估

### 5.1 技术可行性

| 能力 | 现有基础 | 需新增 | 复杂度 |
|---|---|---|---|
| 目录树展示与筛选 | 已有 `/api/kb/folders`、`/api/kb/documents?folder=` | 树组件增强（展开态、搜索、右键菜单） | S |
| 拖拽移动 | 单文档移动 API 已有 | 前端拖拽层、目标判定、批量移动 API | M |
| 批量移动 | 无 | `POST /api/kb/documents/batch-move`，写锁内逐文档更新元数据 | S |
| 撤销 | 无 | 服务端操作日志（operationId + 反向映射）或前端反向调用 | M |
| AI 分类 | 已有嵌入模型、LLM 网关、manifest 目录 | 分类服务（规则+语义+LLM 融合）、目录描述/质心、反馈表 | L |
| 入库路径选择 | 已有 preview/ingest、folder 字段 | 预览接口按需返回分类建议；前端路径选择器 | M |

结论：目录与拖拽为**中低复杂度**，AI 分类为**中高复杂度**；均可基于现有架构增量实现，不需要重建索引。

### 5.2 迁移与兼容风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 目录元数据缺失 | 旧文档无 `folder` 会被目录过滤排除 | 启动自动迁移（已实现，4 文档→6 目录） |
| 移动过程部分失败 | 批量移动若中途异常，出现部分成功 | 服务端写锁内逐条执行并记录成功/失败清单；失败可重试 |
| 并发修改 | 两个管理员同时移动同一文档 | 文档级版本号或 `updated_at` 校验，冲突返回 409 并提示刷新 |
| 撤销越权 | 撤销他人或过期操作 | operationId 绑定用户会话，10 分钟内有效；过期仅提供操作记录 |
| 前端缓存不一致 | 拖拽后本地乐观更新与服务端不一致 | 成功以服务端返回为准；失败回滚并提示 |
| 移动端无拖拽 | 触屏长按拖拽体验差 | 提供"移动到…"菜单与树选择弹窗作为等价入口 |

### 5.3 收益评估

| 收益 | 量化口径 |
|---|---|
| 移动效率 | 单篇 3 步→2 步；20 篇批量 20 次→1 次 |
| 误操作成本 | 从"无法恢复"到"8 秒撤销 + 操作记录" |
| 归档质量 | AI 推荐覆盖 ≥80%，采纳率 ≥60%，减少"未分类"堆积 |
| 检索质量 | 目录归属更准确，目录内检索的信噪比提升 |
| 可维护性 | 目录树成为主入口，后续权限、标签、统计可复用 |

## 7. AI 分类规则体系

### 7.1 分类维度与权重

| 维度 | 信号来源 | 权重 | 说明 |
|---|---|---|---|
| 语义相似 | 文档摘要向量与目录质心的余弦相似度 | 0.40 | 主信号，使用现有嵌入模型 |
| 规则命中 | 关键词、正则、文档类型、型号 | 0.25 | 硬规则可一票否决/直接指定 |
| 标题/文件名 | 设备名、型号、文档类型词 | 0.15 | 低成本高准确 |
| 结构特征 | 页数、表格密度、章节标题、语言 | 0.10 | 区分手册/规程/标准/夹具 |
| 历史行为 | 同用户/同来源的采纳与调整记录 | 0.10 | 冷启动为 0，逐步生效 |

融合公式：

```
final_score = 0.40 * semantic_score
            + 0.25 * rule_score
            + 0.15 * title_score
            + 0.10 * structure_score
            + 0.10 * history_score
```

当 LLM 可用且触发时：

```
semantic_score = 0.70 * embedding_similarity + 0.30 * llm_confidence
```

### 7.2 规则优先级

| 类型 | 语义 | 行为 |
|---|---|---|
| must | 强特征命中（如"评测夹具"、`fixture_` 前缀） | 直接锁定目标目录，跳过其余评分 |
| must_not | 明确排除（空目录、禁用目录、无权限目录、超过 6 级） | 从候选中移除 |
| should | 弱特征（型号、厂商、文档类型词） | 加分，不锁定 |

冲突处理：`must` > `must_not` > `should`；同一文档命中多个 `must` 时按规则配置顺序取第一个，并记录冲突日志。

### 7.3 算法流程

1. **候选集生成**：取全部目录（默认排除空目录与不可写目录），最多 50 个；
2. **规则匹配**：计算 must/must_not/should；命中 must 直接返回；
3. **语义相似**：文档摘要（标题 + 前 800 字 + 主要章节标题 + 表格题注）向量，与目录质心（目录描述向量 + 已有文档摘要向量均值）计算余弦相似度；
4. **LLM 复核**（按需触发）：仅当语义 Top1 <0.72、Top1-Top2 <0.08、或目录无历史质心时调用；要求输出严格 JSON（Top3 路径、置信度、20 字内依据）；超时 8 秒；
5. **融合与校准**：按公式计算，归一化到 0–1；
6. **阈值判定**：
   - `≥0.80`：高置信，推荐首选；
   - `0.60–0.79`：中置信，展示但标记"建议复核"；
   - `<0.60`：不推荐，提示手动选择；
   - `Top1-Top2 <0.05`：标记"存在相近目录"，强制人工确认；
7. **输出**：Top3 候选 + 依据 + 是否可自动创建新目录。

### 7.4 冷启动与增量学习

- **冷启动**：目录无文档时，使用目录描述（人工填写）+ 规则 + LLM 零样本判断；无描述则只用规则与标题；
- **增量**：每次移动/采纳后更新目录质心（增量平均，避免全量重算）；
- **反馈**：采纳、调整、驳回写入 `classification_feedback`；调整/驳回的候选在 30 天内对同一来源降权 0.2；
- 本期不做在线训练，权重通过配置表管理，按季度用标注集回归。

### 7.5 边界处理

| 场景 | 处理 |
|---|---|
| 无任何目录 | 提示"请先创建目录"；可给出新目录建议，但需用户创建 |
| 候选全部低于 60% | 展示"暂无可靠推荐"，默认手动选择，不阻塞入库 |
| 多主题文档 | 只给一个主目录；提示"可在后续版本用标签补充" |
| 目录被并发删除 | 采纳时返回 40402，刷新候选并提示重选 |
| 文档过长 | 摘要截断到 800 字 + 章节标题，不发送全文给 LLM |
| 规则冲突 | must 优先，记录冲突；前端依据文案说明命中的规则 |
| 新目录建议超深/重名 | 路径规范化，超 6 级截断，重名合并到已有目录 |
| LLM/嵌入不可用 | 降级为规则+标题；提示"AI 暂不可用，已使用规则推荐" |

### 7.6 评估指标

| 指标 | 定义 | 目标 |
|---|---|---|
| Top-1 准确率 | 首选目录与人工标注一致 | ≥70% |
| Top-3 准确率 | 前三个候选包含正确目录 | ≥85% |
| 推荐覆盖率 | 至少有一个候选 ≥60% 的文档占比 | ≥80% |
| 采纳率 | 采纳推荐（含微调）的文档占比 | ≥60% |
| 调整率 | 采纳但修改目录的占比 | ≤25% |
| 驳回率 | 明确驳回的占比 | ≤15% |
| 延迟 p95 | 规则+语义 / 含 LLM | ≤3s / ≤8s |
| 误应用次数 | 未经确认自动写入 | 0 |

### 7.7 主流产品策略对比

| 产品/方案 | 分类策略 | 人工参与 | 可借鉴点 | 局限 |
|---|---|---|---|---|
| Microsoft SharePoint Syntex | 以示例文件训练分类器，绑定内容类型，自动分类并抽取字段 | 训练样本、审核 | 内容类型 + 结构化抽取；置信度与人工复核 | 训练与运维重，不适合小团队快速上线 |
| Notion AI Autofill | AI 按预设属性/提示自动填充数据库字段 | 预设规则、人工校验 | 预定义分类选项 + AI 填充，交互简单 | 需要稳定的属性体系，非目录树 |
| RAGFlow | 自动关键词/问题、元数据抽取、知识图谱实体关系 | 配置抽取字段 | 自动元数据与内容增强 | 不直接解决"目录归属" |
| Dify | Dataset → Document → Chunk 扁平结构，元数据人工维护 | 全人工 | 结构简单、实现成本低 | 文档多时管理成本高 |
| WeKnora | 文件夹 + 标签，移动不重解析 | 人工归档 | 目录与标签分离、移动低成本 | 自动分类能力有限 |
| 本方案 | 规则 + 语义质心 + LLM 复核 + 人工确认 | 采纳/调整/驳回 | 可解释、可降级、零自动应用 | 依赖目录描述与历史数据质量 |

结论：采用"规则兜底 + 语义为主 + LLM 复核 + 人工决策"的混合策略，兼顾准确率、可解释性与实现成本；不做监督式模型训练。

## 8. 技术方案与接口

### 8.1 数据模型扩展

manifest 增加目录元信息：

```json
{
  "folder_meta": {
    "设备手册/螺杆空压机": {
      "description": "螺杆式空压机操作、维护、故障处理手册",
      "keywords": ["螺杆", "TS32S", "保养", "故障代码"],
      "centroid": [0.01, 0.23, "..."],
      "doc_count": 1,
      "updated_at": "2026-11-10T22:00:00"
    }
  }
}
```

新增反馈表（SQLite 或 manifest 旁路 JSON）：

```json
{"doc_id": "...", "suggested": "A", "chosen": "B", "action": "adjust", "source": "ingest", "created_at": "..."}
```

### 8.2 新增/调整接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/kb/documents/batch-move` | `{docIds:[], folder}`；返回 `{operationId, moved:[], failed:[]}` |
| POST | `/api/kb/moves/{operationId}/undo` | 10 分钟内可撤销；返回反向结果 |
| POST | `/api/kb/classify` | `{docId}` 或 `{filename, text}`；返回 Top3 候选与依据 |
| POST | `/api/kb/classify/feedback` | `{docId, suggested, chosen, action}` |
| POST | `/api/kb/preview?classify=1` | 预检后附带 AI 候选（可选，耗时操作） |
| GET | `/api/kb/folders?withMeta=1` | 返回目录描述/文档数/块数 |

### 8.3 性能设计

- 目录质心缓存在 manifest，文档入库/移动时增量更新，查询不重算；
- 分类建议默认只做规则+语义（<3s），LLM 仅在低置信时调用（8s 超时）；
- 批量移动在单写锁内逐条更新元数据，返回逐条结果；
- 拖拽交互纯前端，不产生网络请求，释放后才调用批量接口。

## 12. 验收标准

1. 拖拽 1 篇/多篇文档到合法目录，出现顶层放置区高亮与目标目录高亮，释放后弹确认，确认后移动成功；
2. 拖拽到自身、子目录、相同目录、非目录区域时无可放置反馈，不产生请求；
3. 移动成功后 8 秒内可撤销，撤销后目录与文档归属恢复；
4. 批量移动 20 篇文档一次完成，失败项有明确清单；
5. 上传预检后点击"AI 推荐目录"，8 秒内返回 Top3 候选或明确降级提示；
6. AI 候选展示目录、置信度、依据；采纳/调整/驳回均有反馈；
7. 手动选择目录后，AI 结果不覆盖用户选择；
8. 目录内检索结果只包含该子树文档；
9. 原有入库、删除、目录 CRUD、问答链路无回归；
10. 移动端可通过菜单完成移动，键盘可完成筛选与移动入口操作。
